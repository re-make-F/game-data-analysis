# 为什么这次这么快：pandas groupby 自定义函数的坑

> 针对 [analysis.ipynb](../notebook/analysis.ipynb) 第 10 格「3.数据清洗」。
> 2026-11-11 实测，数据在 `data/video_games_sales.csv`（16719 行 × 16 列，1.6 MB）。
> 结论：**从约 20.5 秒降到 148 ms，快约 140 倍。慢的不是数据量，是 22 万次 Python 函数调用。**

---

## 0. 一句话

原来的代码把「取第一个非空值」「判断这一组是否只有一个不同值」写成了 Python 函数，交给 `groupby.agg()` / `transform()` 去**逐组回调**。
这份数据几乎每组只有 1 行，于是 pandas 为 16713 个组、13 个列组合，回调了约 22 万次 Python 函数——**每次都要建 Series、走解释器、拆装箱**，真正干活的 C 代码反而没跑几下。

新写法把这些语义换成 pandas 内置的 C 层聚合（`first` / `sum` / `nunique`），**同样的事在 C 里一次遍历做完**，不再回到 Python。

---

## 1. 实测数据

| 操作 | 原写法 | 新写法 | 倍数 |
|---|---|---|---|
| `first_valid` × 9 个 meta 列 | **12 214 ms** | `groupby.first()` 8.6 ms | ~1400× |
| 评分冲突 `transform(lambda ... nunique)` × 4 列 | **8 099 ms** | `transform('nunique')` 7.3 ms | ~1100× |
| `groupby.sum()` 5 个销量列 | — | 2.3 ms | — |
| **整格合计** | **≈ 20.5 s** | **148 ms** | **≈ 140×** |

其中 `transform(nunique)` 那次单独对比：**8220 ms → 6.6 ms**。

### 关键结构数据

```
总行数   16717
组数     16713          ← 按 (Name, Platform) 分组
组大小   1 行: 16709 组
         2 行: 4 组
单行组   99.98%
```

**这是最要命的一点**：16717 行几乎就是 16713 个组，每组 1 行。
分组数 ≈ 行数，意味着「按组回调」的次数直接等于数据规模，而且每组里几乎没数据可供向量化摊薄开销。

### 单次调用成本

| 调用 | 单次耗时 |
|---|---|
| 纯 Python 空函数 | 0.08 µs |
| `first_valid(1元素Series)` | **65.1 µs** |
| `s.nunique(dropna=False)` 1 元素 Series | **19.1 µs** |

一次 UDF 调用比空函数贵 **800 倍**，因为 pandas 要为每一组：
构造一个 `Series` 子对象 → 从 C 层切回 Python → 调用函数 → 把返回值装箱回 pandas 对象 → 再切回 C。
这些都是**固定开销**，跟组里有没有数据无关。

## 2. 算术：20 秒是怎么攒出来的

原写法两处：

```python
# ① 合并拆分行
agg = {c: 'sum' for c in sales_cols}                 # 5 列
agg.update({c: first_valid for c in meta_cols})      # 9 列 ← 这里是坑
same.groupby(key, as_index=False).agg(agg)

# ② 评分冲突标记
g[sig].transform(lambda s: s.nunique(dropna=False) == 1)   # 4 列 ← 这里也是坑
```

计算量：

```
① 9 列 × 16713 组 = 150 417 次 first_valid 调用
   150417 × 65.1 µs ≈ 9.8 s   （实测 12.2 s，含分组/装箱）

② 4 列 × 16713 组 = 66 852 次 nunique lambda 调用
   66852 × 19.1 µs ≈ 1.3 s    （实测 8.2 s，Series 构造与 transform 开销更大）

合计约 21.7 万次 Python 回调 → 实测 20.5 秒
```

**注意 ① 里 `sum` 用的是字符串 `'sum'`（C 层内置），完全不慢**；
慢的只有那 9 个被写成 `first_valid` 的列。这个对照正好说明问题不在 groupby 本身。

---

## 3. 为什么「内置」能快三个数量级

pandas 的分组聚合有两条完全不同的执行路径：

```
agg({'col': 'sum'})          →  Cython/C 层，一次遍历整个数组，零 Python 回调
agg({'col': 自定义函数})      →  每组切回 Python 解释器，回调一次
transform('nunique')         →  C 层
transform(lambda s: ...)     →  每组切回 Python 解释器，回调一次
```

差别不是「算法更聪明」，而是**有没有跨过 Python ↔ C 那道边界**。
旧写法跨了 21.7 万次，新写法 0 次。

一个直觉类比：
> 旧写法像「让一个人把 16713 封信，每封都单独跑一趟邮局」；
> 新写法像「把 16713 封信一次装车送过去」。
> 信的内容（数据量）没变，变的是跑了多少趟。

## 4. 两处替换为什么**等价**（这最关键，不能只图快）

### 4.1 `first_valid` → `groupby.first()`

原函数：

```python
def first_valid(s):
    """取第一个非空值，跳过 NaN —— 不能用 'first'，否则会取到 NaN"""
    s = s.dropna()
    return s.iloc[0] if len(s) else pd.NA
```

那句注释其实是个误会。pandas 的 `groupby.first()` / `agg('first')` **本身就会跳过 NaN**：
它取的是「每组第一个非空值」，全为空才给 NaN。这正是 `first_valid` 的语义。
会取到 NaN 的是 `s.iloc[0]`（裸取第一行），不是 `'first'`。

```python
# 旧
agg.update({c: first_valid for c in meta_cols})
same.groupby(key, as_index=False).agg(agg)

# 新
g = same.groupby(key, dropna=False)
merged = pd.concat([g[sales_cols].sum(), g[meta_cols].first()], axis=1).reset_index()
```

> 用 `pd.concat([销量sum, 元数据first], axis=1)` 而不是一次 `agg(dict)`，
> 是因为两批列的聚合方式不同，分两次 C 层调用再横向拼起来，比混在一个 agg 里更清楚也更快。

### 4.2 `nunique(dropna=False)` 的语义复现

原写法 `s.nunique(dropna=False) == 1` 里，**NaN 也算一个「不同值」**。
但 pandas 的 `groupby.transform('nunique')` 默认 `dropna=True`（不把 NaN 计入），直接换会改变结果。

所以新写法用哨兵先把 NaN 变成普通字符串，再走内置聚合：

```python
def nunique_with_na(col):
    tmp = (df_analysis[col].astype('object')
           .where(df_analysis[col].notna(), '__NA__'))   # NaN → '__NA__'
    return tmp.groupby([df_analysis['Name'], df_analysis['Platform']],
                       dropna=False).transform('nunique')
```

`NaN` 变成 `'__NA__'` 后，它就是一个货真价实的值，`nunique` 自然会把它算进去，
语义和 `dropna=False` 一致。**哨兵只用于计数，不写回数据**，所以不会污染 df。

## 6. 以后怎么一眼认出这类坑

出现以下任一特征，就要怀疑「Python 回调爆炸」：

1. `groupby(...).agg(自定义函数)` / `apply(lambda ...)` / `transform(lambda ...)`
2. 分组基数很高（组数 ≈ 行数），每组很小
3. 数据不大（几万行）却要跑十几秒
4. 换成 `'sum'` / `'mean'` / `'first'` / `'nunique'` 字符串就飞快

**排查手法**：先单独计时每个 `agg` / `transform`，再数一下组数：

```python
g = df.groupby(key)
print('组数', g.ngroups, '行数', len(df))
g.size().value_counts().sort_index()   # 看是不是几乎全是 1 行组
```

**优先级**：能用内置字符串聚合就别写函数；实在要写自定义逻辑，考虑先
`groupby` 出中间结果再 `merge` 回去，或用 `np` 向量化表达式，避免逐组回调。

## 7. 顺带澄清：另一处慢是独立的

排查时还发现 `.env` 里 `DB_HOST = localhost` 导致**首次连 MySQL 要 2.1 秒**
（Windows 先试 IPv6 `::1` 超时再回落 IPv4），换成 `127.0.0.1` 后是 42 ms。

但那是**每个新连接池一次性**的握手开销，而本格是**每次重跑都花 20 秒**。
两者互不相干，别混在一起。本文件只解释第 10 格这个主因。
